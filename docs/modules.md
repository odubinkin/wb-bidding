# Карта модулей системы

## Как пользоваться картой

Карта связывает архитектурные обязанности с текущими путями исходников. Для порядка вызовов
используйте [справочник реализации](implementation-reference.md), для модели данных —
[справочник таблиц](data-model.md), а для причин защитных ограничений —
[алгоритм](bidding-algorithm.md) и [ADR-0001](adr/0001-fail-closed-wb-contracts.md).

Пути перечислены полностью и проверяются `pnpm run docs:check`. Поэтому перенос или разделение
production TypeScript-модуля требует одновременного обновления этой карты.

| ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `prisma/schema.prisma`, `prisma/migrations/`                                                                     | PostgreSQL-модель и forward-only migrations.                                 |

| `scripts/`                                                                                                       | Profile, fixture, architecture, docs, secret, container и smoke checks.      |
| `Dockerfile`, `Dockerfile.mock`, `docker-compose.yml`, `docker-compose.mock.yml`, `docker-compose.mock-only.yml` | Production read-only, полный mock и независимый mock-only контуры.           |
| `.env.example`                                                                                                   | Полный безопасный шаблон startup-конфигурации без действительных секретов.   |

Для изменения бизнес-правила проследите путь `decision-engine → data-sync → write-pipeline`. Для
HTTP-контракта обновляйте controller/DTO, OpenAPI и contract tests вместе. Для WB-интеграции сначала
меняются pinned profile и fixtures, затем registry, schemas, mock и adapter.
